UML 部署图实战：Web-应用-数据库三层架构设计

UML 部署图 三层架构 Nginx

为什么需要部署图？

UML 部署图（Deployment Diagram）用于描述系统的物理部署架构，展示软件组件如何分布在硬件节点上。在真实项目中，部署图是运维和架构沟通的重要工具。

标准三层架构

┌─────────────────────────────────────────┐
│              Web 服务器层                │
│  ┌─────────┐  ┌─────────┐              │
│  │ Nginx 1 │  │ Nginx 2 │  (负载均衡)   │
│  └─────────┘  └─────────┘              │
├─────────────────────────────────────────┤
│             应用服务器层                 │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐│
│  │  App 1   │ │  App 2   │ │  App 3   ││
│  └──────────┘ └──────────┘ └──────────┘│
├─────────────────────────────────────────┤
│             数据库服务器层               │
│  ┌──────────┐      ┌──────────┐        │
│  │  Master  │──────│  Slave   │        │
│  └──────────┘      └──────────┘        │
└─────────────────────────────────────────┘

节点规范

Web 服务器（Nginx）

  • 职责：反向代理、负载均衡、静态资源服务
  • 协议：HTTP/HTTPS
  • 端口：80/443

应用服务器

  • 职责：业务逻辑处理
  • 技术栈：Spring Boot + Tomcat
  • 端口：8080（内网）

数据库服务器

  • 职责：数据持久化
  • 架构：主从复制（Master-Slave）
  • 端口：3306（内网）

关键设计考量

  1. 负载均衡算法：建议使用 least_conn（最少连接数）
  2. 健康检查：Nginx 定期探测应用服务器状态
  3. 数据库读写分离：主库写、从库读
  4. 网络隔离：数据库层只允许应用服务器访问
